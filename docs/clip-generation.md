# Выбор моментов и экспорт клипов

Локальный конвейер: существующая расшифровка → Qwen → проверка и глобальное ранжирование → FFmpeg → MP4 и JPEG. Он подключён к фоновому worker сайта и не обращается к платным API.

## Требования

Уже установленные FFmpeg с libass, yt-dlp, llama.cpp и модель `storage/models/Qwen3-4B-Q4_K_M.gguf` (~2.5 GB). Модель скачана из [официального репозитория Qwen](https://huggingface.co/Qwen/Qwen3-4B-GGUF). `llama-completion` установлен вместе с зависимостями whisper.cpp. Для новой машины: `brew install llama.cpp`.

```sh
curl -fL --retry 2 -o storage/models/Qwen3-4B-Q4_K_M.gguf.part https://huggingface.co/Qwen/Qwen3-4B-GGUF/resolve/main/Qwen3-4B-Q4_K_M.gguf
```

Только после успешной загрузки переименовать `.part` в `.gguf`. Шаблон запроса сейчас предназначен для Qwen3 (ChatML, без thinking). Для другой совместимой Qwen3-модели использовать `CLIP_LLM_MODEL`; для другого расположения CLI — `LLAMA_CLI`. Число CPU-потоков задаёт `CLIP_LLM_THREADS` (по умолчанию 3). Автоматический переход с Metal на CPU отключён, чтобы неожиданно не создавать длительную высокую нагрузку; его можно явно разрешить через `CLIP_LLM_ALLOW_CPU=1`. Переменные задаются в окружении, `.env` этой командой автоматически не читается. Prompt и ответы сохраняются локально для диагностики; не отправляются внешнему провайдеру.

## Запуск

```sh
npm run media:clips -- storage/benchmarks/34HF78uOe1k-1789524727895
```

По умолчанию до двух клипов, субтитры включены. `--no-subtitles` отключает их. `--both` создаёт каждый выбранный фрагмент в обоих вариантах. `--count 1`–`5` задаёт верхнюю границу количества. Если подходящих эпизодов мало, модель может вернуть меньше или ни одного.

В форме сайта доступны два профиля. **Eco** выбран по умолчанию: Whisper использует 2 потока, Qwen 3, FFmpeg 2 и между блоками отбора есть пауза 1,5 секунды. Для H.264 применяется `ultrafast`, поэтому файл может быть больше. **Fast** использует до 6 потоков для Whisper и Qwen и более плотное кодирование. Профиль сохраняется в проекте и используется при повторном запуске.

При отсутствии видео команда скачает начальный фрагмент YouTube до длительности расшифровки. Для уже скачанного исходника:

```sh
npm run media:clips -- storage/benchmarks/34HF78uOe1k-1789524727895 --video storage/video/34HF78uOe1k/source.mp4 --both
```

`--video` — внутренний параметр локального разработчика, не загрузка файла в интерфейсе. Файл обязан соответствовать тому же YouTube-ролику и начинаться с нулевой отметки; команда проверяет дорожки и длительность, но не устанавливает идентичность содержимого. Не передавать произвольный другой файл.

## Выбор и ограничения

Код заранее строит интервалы из соседних сегментов. Расшифровка передаётся модели один раз, а интервалы содержат только границы: это заметно уменьшает контекст и нагрузку по сравнению с повторением полного текста для каждого кандидата. Рекламные интервалы отсекаются до вызова модели по коммерческим призывам, бонусам, промокодам и ссылкам. Модель выбирает ID, заголовок, дословную подтверждающую цитату и оценку. Сервер вычисляет секунды сам и проверяет содержание. Если заголовок добавляет отсутствующее слово или факт, он заменяется коротким заголовком из слов подтверждающей цитаты; если цитата неточная, выбирается наиболее подходящее предложение из исходного фрагмента. Один некорректный кандидат пропускается и больше не останавливает весь проект. Затем кандидаты всех блоков ранжируются вместе; вступление и близкие дубликаты исключаются.

Сайт анализирует ролик целиком десятиминутными участками с перекрытием до 45 секунд, поэтому законченная мысль на границе участков не теряется. Общий предел задаётся `MEDIA_TOTAL_ANALYSIS_SECONDS` и по умолчанию совпадает с максимальной поддерживаемой длительностью ролика — 120 минут. Старая переменная `MEDIA_MAX_ANALYZED_SECONDS`, ограничивавшая анализ первыми 10 минутами, больше не используется. Внутри каждого участка расшифровка дополнительно делится на адаптивные модельные блоки: один запрос ограничен 210 секундами, 500 сегментами и размером контекста. Кандидаты со всех участков ранжируются вместе, пересечения и смысловые дубли удаляются. По умолчанию планируется примерно два сильных клипа на каждые начатые 10 минут, но не более 30 на проект; выбранное в форме число является гарантированным минимумом, а не жёстким максимумом. Слабый участок может не дать ни одного клипа, а сильный — дать несколько. Речь распознана автоматически и содержит ошибки; выбор моментов наследует их.

## Экспорт

720×1280 (9:16), H.264, AAC, MP4 faststart; рядом JPEG-превью. По умолчанию полный исходный кадр вписан в чёрный фон. Опциональный AI reframing на macOS извлекает уменьшенный кадр раз в 6 секунд в Eco или раз в 3 секунды в Fast, Apple Vision выбирает крупнейшее лицо, координаты сглаживаются, а FFmpeg плавно перемещает вертикальный crop. Если лицо или Vision недоступны, применяется полный кадр без ошибки проекта.

Новые проекты используют `--output-json-full` whisper.cpp и сохраняют временные метки токенов. Субтитры собираются в фразы до 30 символов или 2,4 секунды и располагаются выше нижних элементов интерфейса Shorts. Полнота токенов проверяется относительно текста сегмента; при недостаточных или некорректных данных используется прежнее пропорциональное распределение фразы. Старые кэшированные расшифровки автоматически используют этот резерв. Экспериментальный DTW не включён.

Итоги в `storage/clips/<videoId>-<timestamp>/`: selection.json, result.json, status.json, каталоги клипов. Готовые результаты записываются после каждого экспорта; при поздней ошибке остаются в status.json. Незавершённый MP4 не выдаётся за готовый; ffprobe проверяет кодеки, звук, размер кадра и длительность. Исходник и prompt остаются на диске для диагностики.

Одна команда одновременно, lock `storage/clips.lock`. После аварийного выключения удалить его вручную только убедившись, что соответствующий процесс больше не работает. Общая очередь с распознаванием пока не реализована: не запускать одновременно media:benchmark и media:clips. Для публичного сервиса нужны авторизация, проверка владельца, лимиты, постоянная очередь и безопасное восстановление.

Worker сайта сохраняет PID в SQLite. Кнопка «Остановить обработку» переводит проект в `cancelling`, отправляет `SIGTERM`, а общий `AbortController` завершает текущий `yt-dlp`, Whisper, Qwen или FFmpeg вместе с его группой процессов. После очистки временных файлов проект получает статус `cancelled`; исходник и готовая расшифровка сохраняются для повторного запуска.

## Проверки

`npm run test:media` и `npm run typecheck`. Помимо тестов выполняется реальный монтаж с субтитрами и без них, техническая проверка MP4 и визуальная проверка JPEG. Полная оценка качества требует прослушивания.

## Результат реального запуска

На первых 180 сек ролика 34HF78uOe1k модель выбрала один непересекающийся интервал 0–35 сек. Выбор 16.6 сек, с двумя экспортами из уже скачанного видео — 22.4 сек, без времени первоначальной загрузки модели и видео. Два MP4 прошли проверки ffprobe. 19 тестов и TypeScript прошли.

Первый сквозной запуск обнаружил два дефекта: ранняя реклама выигрывала из-за сортировки по времени, а свободный заголовок мог добавлять отсутствующие детали. Новый алгоритм исправляет оба пути статическими проверками и глобальным ранжированием. Повторная качественная оценка на реальном ролике отложена, чтобы не нагружать устройство; до неё не заявляем, что качество отбора подтверждено.

Результаты: `storage/clips/34HF78uOe1k-1789548968741/result.json`. Субтитры приблизительные, ошибки ASR не исправлялись.
