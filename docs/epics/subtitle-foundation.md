# SUBTITLE-01 — Надёжный фундамент субтитров

Статус: завершён. Контрольный GPU-прогон, интеграция worker, словесные таймкоды, кэширование и сквозная пользовательская проверка выполнены успешно.

Связанные эпики: `MEDIA-03` (распознавание речи) и `MEDIA-05` (рендер клипов и субтитров).

## Результат

Конвейер получает качественную русскую расшифровку и устойчивые временные границы **целых слов**. Один и тот же сохранённый результат можно повторно использовать для разных стилей субтитров, подсветки ключевых слов, автоцензора и эмодзи без повторного распознавания аудио.

Этот эпик создаёт фундамент. Выбор соотношения сторон, длительности клипов, библиотека визуальных шаблонов, автоцензор и эмодзи входят в следующие эпики.

## Проблема

Текущий `whisper.cpp` с multilingual-моделью сохраняет сегменты и внутренние токены модели. Токен не равен слову: одно слово может состоять из нескольких частей, а пробел может быть частью соседнего токена. Поэтому прямое построение субтитров из токенов приводит к результатам вроде `пол уч ил` или к склеиванию нескольких слов.

Фразовые сегменты дают целый текст, но их недостаточно для точной подсветки произносимого слова, звукового цензора и аккуратных динамических шаблонов.

## Архитектурное решение

Конвейер разделяется на три независимых слоя:

1. **ASR:** получает нормализованный текст фраз и приблизительные временные границы.
2. **Word alignment:** сопоставляет целые слова нормализованного текста с аудио и возвращает начало и конец каждого слова.
3. **Caption composition:** объединяет готовые слова в визуальные группы по 1–2 слова. Этот слой не читает внутренние ASR-токены.

Кандидат основного стека для компьютера с RTX 4080:

- `faster-whisper` с CUDA и моделью `large-v3-turbo` для распознавания;
- WhisperX либо другой совместимый forced aligner для границ целых русских слов;
- сохранение результата в версионированный JSON;
- существующие FFmpeg и ASS для первого статического рендера.

Стек считается выбранным только после локального сравнительного прогона. Если WhisperX для русского языка или Windows окажется нестабилен, допускается другой aligner либо временный переход на сегментные субтитры без ложной точности.

## Контракт данных

Расшифровка хранится отдельно от визуального представления:

```ts
interface AlignedWord {
  id: string;
  text: string;
  normalized: string;
  start: number;
  end: number;
  confidence: number | null;
}

interface AlignedSegment {
  id: string;
  text: string;
  start: number;
  end: number;
  words: AlignedWord[];
}

interface TranscriptArtifact {
  schemaVersion: 2;
  language: string;
  model: string;
  aligner: string | null;
  audioFingerprint: string;
  segments: AlignedSegment[];
}
```

Инварианты:

- текст слова никогда не собирается простым соединением ASR-токенов;
- границы слов монотонны и находятся внутри соответствующего сегмента;
- пробелы и пунктуация восстанавливаются из нормализованного текста;
- служебные элементы (`[_TT_250]`, `<|...|>` и аналоги) не попадают в пользовательский текст;
- исходная расшифровка не изменяется при выборе стиля или повторном рендере;
- артефакт содержит версии схемы, модели и aligner, чтобы кэш можно было безопасно инвалидировать.

## Задачи

### SUB-01.1 — Зафиксировать контрольные материалы

- Выбрать 3 коротких русских фрагмента: чистая речь, разговор с музыкой и шумный игровой/развлекательный ролик.
- Добавить случаи с длинными словами, числами, именами, англицизмами, паузами и ненормативной лексикой.
- Подготовить небольшой вручную проверенный эталон текста и границ слов.
- Не хранить защищённые авторским правом видео в Git; документировать источник и локальный путь к образцу.

### SUB-01.2 — Сравнить ASR и выравнивание на RTX 4080

- Поднять изолированное Python-окружение для `faster-whisper` и кандидата aligner.
- Проверить CUDA, объём видеопамяти, время запуска, скорость и пиковую память.
- Сравнить текущий `whisper.cpp` и новый стек на одинаковом аудио.
- Зафиксировать ошибки слов, пропуски, служебные токены и качество границ.
- Выбрать модель, compute type, число потоков и безопасный fallback на CPU.

### SUB-01.3 — Ввести версионированный формат расшифровки

- Добавить runtime-валидацию `TranscriptArtifact`.
- Сохранять модель, aligner, язык, fingerprint аудио и параметры запуска.
- Не перезаписывать валидный кэш при сбое новой попытки.
- Старый формат читать только через явный адаптер; не смешивать старые токены с новым словесным форматом.

### SUB-01.4 — Интегрировать ASR-процесс с worker

- Запускать ASR без shell-интерполяции и с поддержкой отмены и timeout.
- Передавать стадии распознавания и выравнивания в состояние проекта.
- Записывать временный результат и атомарно публиковать его после валидации.
- Повторный рендер с тем же аудио должен использовать кэш.
- Понятно сообщать об отсутствии CUDA, модели или совместимого aligner.

### SUB-01.5 — Нормализовать слова

- Удалять служебные токены до сохранения пользовательского текста.
- Сохранять целые слова, апострофы, дефисы, числа и связанную пунктуацию.
- Не вставлять пробелы внутрь слова на основании границ токенов.
- Не склеивать соседние слова при отсутствии пробела в токене.
- Помечать слова без надёжного выравнивания и использовать для них границы сегмента.

### SUB-01.6 — Перевести компоновщик субтитров на слова

- Формировать экранные группы из 1–2 объектов `AlignedWord`.
- Не разрывать одно слово между событиями ASS.
- Ограничивать длительность слишком коротких вспышек, не создавая перекрытий.
- Использовать сегментный fallback, если словесное выравнивание недоступно.
- Оставить визуальный стиль независимым от текста и временных границ.

### SUB-01.7 — Миграция и повторная генерация

- Не считать старые token-based расшифровки совместимыми со словесной подсветкой.
- При необходимости новой точности предложить один раз обновить расшифровку проекта.
- После успешной миграции повторный рендер не должен запускать ASR.
- Не удалять старый артефакт до успешного создания нового.

### SUB-01.8 — Диагностика

- Логировать версии модели и схемы, режим CUDA/CPU и длительность этапов.
- Не выводить полный текст расшифровки в обычный серверный лог.
- Сохранять технический отчёт рядом с артефактом проекта.
- Отделить ошибку распознавания от ошибки выравнивания и рендера.

## Критерии приёмки

- В контрольных примерах отсутствуют слова, разделённые на ASR-токены (`пол уч ил`), и соседние склеенные слова.
- В пользовательских субтитрах нет служебных маркеров в квадратных или угловых скобках.
- Каждое выровненное слово имеет конечные, монотонные `start` и `end`, причём `end > start`.
- Экранная группа содержит не больше двух целых слов.
- Для русского контрольного материала медианная ошибка границ слов не превышает 150 мс, а 95-й процентиль — 350 мс. Если инструмент не достигает порога, функция словесной анимации не считается готовой.
- Результат одинаково корректно формируется для белого, жёлтого, зелёного и синего оформления: цвет не влияет на распознавание и тайминг.
- Повторная генерация клипов с другим стилем использует сохранённую расшифровку и не запускает ASR заново.
- Отмена процесса не публикует повреждённый JSON и не уничтожает предыдущий валидный кэш.
- При отсутствии выравнивания система создаёт корректные фразовые субтитры и явно фиксирует fallback, а не имитирует точность отдельных слов.

## Не входит в эпик

- интерфейс выбора соотношения сторон и длительности клипа;
- библиотека визуальных шаблонов;
- анимация, подсветка ключевых слов и караоке-эффект;
- автоцензор и модификация звука;
- автоматические эмодзи;
- удаление пауз, B-roll и редактор субтитров.

## Риски

- CUDA-зависимости Python могут конфликтовать с установленными версиями драйвера и библиотек; окружение должно быть изолированным и воспроизводимым.
- Forced alignment для русского языка необходимо проверить экспериментально, а не принимать качество английских примеров за гарантию.
- `large-v3-turbo` повысит требования к диску и первому запуску; загрузка модели должна быть отдельной понятной операцией.
- Низкокачественный звук и одновременная речь не всегда позволяют получить точные границы; fallback обязателен.
- Изменение модели требует инвалидировать кэш по версии и fingerprint, иначе проект может использовать несовместимые данные.
