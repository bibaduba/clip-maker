# Продуктовые эпики

Статус: согласованный объём продукта переведён в план; функциональность ещё не реализована.

## Границы первой версии

Личный сервис для русскоязычных подкастов, развлекательных видео и записей стримов с YouTube. Пользователь вставляет ссылку, получает автоматически выбранные фрагменты, просматривает и скачивает готовые клипы. Обработка выполняется на его устройстве; первоначальный бюджет — ориентировочно 1000–1500 ₽ в месяц. В дальнейшем сервис должен поддерживать других пользователей.

В первой версии нет загрузки файлов, других видеоплощадок, публикации в соцсети, биллинга, обещаний «вирусности» и полноценного видеоредактора. Поиск фрагментов по речи подходит прежде всего для разговорных эпизодов; обнаружение визуальных событий без речи — отдельное будущее улучшение.

Стек интерфейса: Next.js, TypeScript, SCSS Modules. Каждый компонент подключает свой файл через `import styles from './index.module.scss'`. Основной инструмент раскладки — Flexbox; Grid допустим только при обоснованной необходимости.

## P1. Оболочка приложения и визуальная система

**Результат:** минималистичный адаптивный интерфейс с навигацией «Проекты» и «Настройки». Референс задаёт просторную композицию, но продукт получает собственные цвета, типографику и компоненты.

**Задачи:**
- Определить токены цветов, размеров, радиусов, отступов и типографики через CSS custom properties.
- Создать компоненты кнопки, поля, чекбокса, выбора темы, уведомления, диалога и индикатора состояния.
- Сделать оболочку рабочего пространства и компактную навигацию для узкого экрана.
- Подготовить состояния загрузки, пустого списка и ошибки.

**Критерии приёмки:**
- Основные экраны работают на ширине от 360 px без горизонтального скролла.
- Светлая, тёмная и системная темы используют общие семантические токены.
- Все интерактивные элементы доступны с клавиатуры, имеют видимый фокус и понятные подписи.
- Нет глобальных стилей компонентов, дублирования крупных фрагментов разметки и ненужных Grid-раскладок.
- Демонстрационные данные явно помечены и не выдаются за результат работающего ИИ.

**Зависимости:** фундамент проекта. Владелец реализации: frontend.

## P2. Авторизация и жизненный цикл аккаунта

**Результат:** регистрация и вход по логину/паролю либо через Google; проекты принадлежат конкретному пользователю с первого дня.

**Задачи:**
- Реализовать формы регистрации, входа и выхода с серверной валидацией.
- Определить уникальность и нормализацию логина; хранить отображаемый логин отдельно от стабильного ID пользователя.
- Настроить Google OAuth и локальные callback URL с понятным описанием требуемых credentials.
- Реализовать защищённые сессии, ограничение попыток входа и безопасное хеширование паролей средствами выбранной auth-библиотеки.
- Для первого личного запуска закрыть публичную регистрацию после создания владельца; будущий доступ других пользователей включать явно.

**Критерии приёмки:**
- Неавторизованный пользователь не получает проекты, исходники, клипы или настройки через страницу либо API.
- Каждый запрос чтения/изменения проекта и каждый доступ к файлу проверяет владельца на сервере. Знание чужого ID не даёт доступа.
- Выход завершает текущую сессию; cookies сессии имеют корректные настройки HttpOnly, SameSite и Secure для выбранного окружения.
- OAuth проверяет state и остальные защитные параметры средствами библиотеки; секреты не попадают в клиентскую сборку или логи.
- Совпадение email само по себе не объединяет аккаунты. Привязка Google к существующему аккаунту требует аутентифицированной сессии и подтверждения владения способом входа.
- При отсутствии OAuth credentials интерфейс честно сообщает о недоступности Google, а парольный вход остаётся рабочим.
- Для локального аккаунта без email нет фиктивной кнопки восстановления по почте: до публичного запуска документируется процедура восстановления владельцем локального сервера.

**Зависимости:** база данных, выбор auth-библиотеки, P1. Владелец реализации: backend/auth.

## P3. Создание проекта по YouTube-ссылке

**Результат:** пользователь запускает одну обработку, понимает её параметры и видит текущий этап.

**Задачи:**
- Сделать поле YouTube URL, отдельный чекбокс «Добавить субтитры», выбор количества и длительности клипов в пределах лимитов worker.
- Показать язык «Русский», доступные параметры вертикального кадра и пояснение про анализ речи.
- После создания проекта открывать его страницу со статусом обработки.
- Отображать этапы: ожидание, получение видео, распознавание, поиск фрагментов, монтаж, готово, ошибка.

**Критерии приёмки:**
- Сервер принимает только поддерживаемые варианты YouTube URL; неверная ссылка не создаёт задачу.
- URL проверяется на сервере и безопасно передаётся загрузчику без интерполяции в shell. Произвольные адреса, локальные ресурсы и обход через редиректы не допускаются.
- Снятый чекбокс исключает субтитры из итогового видео, но не отключает транскрибацию для анализа.
- Повторное нажатие кнопки во время отправки не создаёт дубликаты задач.
- Закрытие и открытие вкладки сохраняет проект и его статус. Выключенное устройство останавливает локальную обработку; интерфейс не обещает работу в облаке.
- Нет выдуманного процента выполнения: при отсутствии точной оценки показывается этап и индикатор ожидания.
- Ошибки загрузки, приватного/недоступного ролика, лимита длительности и сбоя обработки имеют понятное описание без внутренних секретов.

**Зависимости:** P1, P2, API проектов и очередь worker. Владелец реализации: frontend + backend.

## P4. История и результаты

**Результат:** пользователь возвращается к прошлым проектам, просматривает и скачивает клипы.

**Задачи:**
- Сделать список проектов с названием, датой, превью, количеством результатов и статусом.
- На странице проекта показать исходную YouTube-ссылку, параметры генерации и карточки клипов.
- Добавить воспроизведение, скачивание, повтор после ошибки и удаление проекта.
- Отобразить состояние частично готовых результатов и истёкшего срока хранения файла.

**Критерии приёмки:**
- История сохраняется после выхода и повторного входа; сортировка по дате стабильна.
- Каждый готовый клип воспроизводится и скачивается; название файла корректно для распространённых ОС.
- Повтор после ошибки не дублирует уже сохранённые результаты без необходимости и не создаёт неконтролируемые параллельные задачи.
- Удаление требует явного подтверждения, снимает проект с обработки при возможности и запускает удаление связанных файлов по контракту worker.
- Файл, удалённый политикой хранения, помечается недоступным; кнопка скачивания не ведёт на сломанную ссылку.
- Даже в личной версии выдача файлов требует проверки пользователя; публичная статическая директория не используется для приватных роликов.

**Зависимости:** P2, P3, хранилище и результаты worker. Владелец реализации: frontend + backend.

## P5. Настройки профиля и оформления

**Результат:** пользователь меняет логин, управляет локальным паролем и выбирает тему.

**Задачи:**
- Создать секции «Профиль», «Безопасность» и «Внешний вид».
- Поддержать изменение логина с проверкой уникальности.
- Поддержать изменение локального пароля с подтверждением текущего пароля.
- Добавить отдельный сценарий установки локального пароля для Google-only аккаунта после повторной проверки Google-входа.
- Сохранять тему «Светлая / Тёмная / Системная» в настройках пользователя с ранним применением на странице.

**Критерии приёмки:**
- Изменение логина не меняет владельца истории: связи используют неизменяемый user ID.
- Google-only аккаунту не предлагается ввести несуществующий текущий пароль; интерфейс объясняет установку пароля для этого сайта. Пароль Google сайт не меняет.
- После смены/установки пароля применяется явно выбранная политика отзыва других сессий.
- Нельзя удалить последний рабочий способ входа.
- Системная тема следует за настройкой ОС, ручная сохраняется между посещениями; при загрузке нет заметного переключения противоположной темы.
- Ошибки сохранения не маскируются успешным уведомлением и не уничтожают заполненные пользователем данные.

**Зависимости:** P1, P2. Владелец реализации: frontend + backend/auth.

## Порядок и проверка

Сначала согласовать типы пользователя, проекта, параметров, статусов и клипа. Затем P1 и backend auth выполняются параллельно; P3 подключается к реальному worker, после него — P4. P5 можно делать после авторизации независимо от обработки видео.

Обязательные проверки перед завершением MVP: полный путь от входа до скачивания русского клипа; генерация с субтитрами и без них; сохранение истории после перезапуска; проверка доступа двумя разными пользователями; парольный и Google-вход; профиль Google-only; ошибки недоступного YouTube-видео; поведение после прерывания worker; очистка файлов; мобильный экран и обе темы. Проверка двумя аккаунтами обязательна даже при первом личном использовании, поскольку изоляция данных заложена как основа будущего сервиса.
