# Подготовка к публичному режиму

Локальная версия уже разделяет проекты и файлы по владельцам, хранит сессии в HttpOnly cookie, хеширует пароли через scrypt, ограничивает повторные попытки входа и принимает только проверенные параметры обработки. Этого достаточно для личного запуска, но недостаточно для публичного сервиса.

Перед открытием регистрации:

1. Перенести пользователей, сессии, проекты, задания и метаданные клипов из SQLite в PostgreSQL с миграциями и внешними ключами.
2. Вынести обработку в постоянную очередь. Задание должно иметь lease, число попыток и heartbeat, чтобы после перезапуска его мог подобрать другой worker без дубликатов.
3. Хранить видео и превью в приватном объектном хранилище, выдавая короткоживущие подписанные ссылки после проверки владельца.
4. Добавить распределённый rate limit для входа, регистрации и создания проектов, квоты на длительность, диск и число параллельных заданий пользователя.
5. Добавить CSRF-защиту для изменяющих запросов, журнал событий безопасности, ротацию сессий и автоматическую очистку просроченных сессий и файлов.
6. Запускать worker в изолированном окружении без доступа к секретам веб-приложения и ограничивать CPU, память, время и размер скачивания.
7. Проверить два аккаунта, восстановление задания после аварии, повторную доставку одного сообщения, истечение сессии и невозможность скачать чужой клип.

Для текущего бюджета и запуска на одном Windows-компьютере PostgreSQL и внешняя очередь добавят обслуживание, но не дадут практической пользы. Их следует подключать при выборе хостинга перед первой публичной регистрацией.
